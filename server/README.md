# 元宝搜索对接说明

把腾讯云**元宝搜索**（Tencent Yuanbao Search，产品代号 `wsa`）接入衡源风控的后端网关。

## 为什么必须走后端

| 问题 | 说明 |
| --- | --- |
| 签名需要密钥 | 调用要用 `SecretKey` 做 TC3-HMAC-SHA256 签名，放前端等于公开泄露 |
| 跨域限制 | `wsa.tencentcloudapi.com` 不支持浏览器直接跨域调用 |
| 时间戳校验 | 签名基于服务端时间戳，前端时钟不可信 |

所以链路是：**浏览器 → 本地/线上后端 → 元宝搜索 API**。

## 开通步骤

1. 注册腾讯云账号并完成实名认证
2. 进入 [元宝搜索控制台](https://console.cloud.tencent.com/wsapi/index) 开通服务
3. 到 [API 密钥管理](https://console.cloud.tencent.com/cam/capi) 创建密钥
   - 建议用**子账号**，只授予 `QcloudWSAFullAccess`，不要用主账号密钥
4. 复制 `.env.example` 为 `.env`，填入密钥

```bash
cp server/.env.example server/.env
```

## 启动

```bash
node server/server.js
# 衡源风控 已启动  http://127.0.0.1:4174/
```

浏览器打开 <http://127.0.0.1:4174/>，静态页面和 API 同源，无需配置跨域。

## 怎么验证接口通了（不需要密钥也能测）

打开 **<http://127.0.0.1:4174/debug>** —— 这是可视化的接口自测台，分三步：

| 步骤 | 作用 | 需要密钥 |
| --- | --- | --- |
| 1 · 链路自检 | 用假密钥发一次真实请求，验证签名算法、请求头、网络是否全对 | 不需要 |
| 2 · 单次检索 | 调 `/api/search`，表格展示 `Pages` 的标题/域名/日期/相关度/权威度 | 需要 |
| 3 · 企业巡检 | 调 `/api/inspect`，展示 4 类 Query 映射出的风险事件 | 需要 |

步骤 1 的判定标准：腾讯云返回 `AuthFailure.SecretIdNotFound` 且带 `RequestId`，
说明**请求已被腾讯云受理**，只差有效密钥；如果返回签名错误或超时，才是代码/网络问题。

自测台支持 URL 参数，方便演示与截图：

| 参数 | 作用 |
| --- | --- |
| `?auto=1` | 打开即自动跑一次链路自检 |
| `?auto=inspect` | 打开即自动跑一次企业巡检 |
| `?name=企业全称` | 预填巡检表单的企业名 |

例：`http://127.0.0.1:4174/debug?name=蜜雪冰城股份有限公司&auto=inspect`

命令行等价写法：

```bash
# 链路自检（假密钥，预期返回 AuthFailure.SecretIdNotFound）
curl -X POST http://127.0.0.1:4174/api/selftest -H "Content-Type: application/json" -d '{}'

# 单次检索（需先配密钥）
curl -X POST http://127.0.0.1:4174/api/search \
  -H "Content-Type: application/json" \
  -d '{"query":"华东智造设备有限公司 行政处罚","mode":2,"industry":"gov","freshness":"d7","cnt":10}'

# 不启服务，直接调客户端
node server/tencent-wsa.js "华东智造设备有限公司 行政处罚"
```

> 注意：主应用页面 <http://127.0.0.1:4174/> 目前仍使用 `data.js` 的演示数据，
> 尚未调用 `/api/inspect`。侧边栏「数据源状态」会显示 `DEMO · 未配置密钥`
> 或 `SearchPro / gov · ONLINE`，用于提示当前数据来源。

## 接口

### `GET /api/health`

返回密钥是否已配置。

### `POST /api/search`

单次检索，参数直接透传给 `SearchPro`。

```json
{
  "query": "华东智造设备有限公司 行政处罚",
  "mode": 2,
  "industry": "gov",
  "freshness": "d7",
  "cnt": 10,
  "deeplinks": true
}
```

### `POST /api/selftest`

链路自检。用假密钥发真实请求，返回 `reachedCloud` / `code` / `requestId` / `verdict`，
以及本次请求的签名头样本（`signedRequest`），用于排查签名问题。不消耗额度。

### `POST /api/inspect`

企业巡检：对每家企业自动拆解 4 类 Query（行政处罚 / 经营异常 / 招投标 / 资质到期），
返回已映射为 `riskEvents` 结构、且只采信官方域名的风险事件。

```json
{
  "companies": [{ "id": "company-1", "name": "华东智造设备有限公司", "code": "91310000MA1K4H2M8X" }],
  "freshness": "d7",
  "cnt": 10
}
```

返回三组结果：

| 字段 | 含义 |
| --- | --- |
| `risks` | 达到采信标准（`confidence` = `strong` / `medium`）的风险事件 |
| `leads` | 弱证据线索：仅正文提及企业名等，**不计入风险库**，供人工核实 |
| `errors` | 单条 Query 调用失败（含错误码与 RequestId），不影响整批 |

单次最多 5 家企业，防止打满 QPS。

### `POST /api/company`

企业主体（工商登记）查询。**注意：这不是元宝搜索提供的**，必须另接一家企业征信数据源。

```json
{ "name": "蜜雪冰城股份有限公司" }
```

未配置数据源时返回 `503` + `code: "NO_PROVIDER"`：

```json
{
  "ok": false,
  "error": "未配置企业征信数据源",
  "code": "NO_PROVIDER",
  "hint": "在 server/.env 配置 QCC_KEY + QCC_SECRET_KEY（企查查）或 TYC_TOKEN（天眼查）后重启"
}
```

配置成功后返回：

```json
{
  "ok": true,
  "provider": "qcc",
  "providerName": "企查查",
  "profile": {
    "name": "蜜雪冰城股份有限公司",
    "creditCode": "91410100MA3X...",
    "status": "存续",
    "legalPerson": "张红超",
    "regCapital": "36000万人民币",
    "actualCapital": "36000万人民币",
    "establishedAt": "2008-04-30",
    "staffCount": "3000",
    "businessScope": "……",
    "address": "河南省郑州市……",
    "industry": "餐饮业"
  }
}
```

#### 配置哪一家？

二选一即可，`company-provider.js` 按 `.env` 里存在哪个 key 自动选择：

| 数据源 | `.env` 配置 | 申请地址 | 备注 |
| --- | --- | --- | --- |
| 企查查 | `QCC_KEY` + `QCC_SECRET_KEY` | https://openapi.qcc.com/ | 签名 `Token = MD5(key + timespan + secretKey).toUpperCase()` |
| 天眼查 | `TYC_TOKEN` | https://open.tianyancha.com/ | 请求头 `Authorization: token` |

```bash
# server/.env
QCC_KEY=你的key
QCC_SECRET_KEY=你的secret
# 或者
TYC_TOKEN=你的token
```

改完必须重启 `node server/server.js`，`/api/health` 的 `companyProvider.configured` 会变成 `true`。

#### 为什么「别的平台能查到，我们查不到」

企查查 / 水滴信用 / 启信宝页面上那些字段——成立时间、法定代表人、注册资本、实缴资本、
参保人数、涉诉、失信、备案、商标——全部来自**结构化企业征信数据库**，
靠网页搜索永远拿不到。元宝搜索返回的是「和这串字相关的公开网页」，两者不是一回事。

所以本系统的分工是：

- **主体画像** → `/api/company`（征信 API，要 key）
- **风险事件** → `/api/inspect`（元宝搜索，已通）

没配 key 时，前端「查主体」抽屉会给出企查查 / 天眼查 / 爱企查 / 国家企业信用信息公示系统的
一键跳转入口，方便人工核对，不会假装查到了。

### 判级规则（为什么不是「关键词命中就算风险」）

政府网站上「处罚」「招标」「资质」这类词遍地都是，只做关键词匹配会大面积误报。
实测：查「深圳市腾讯计算机系统有限公司 行政处罚」，返回的是《不合格食品核查处置通告》，
正文只有一句「微信平台（深圳市腾讯计算机系统有限公司）」——这是**提到**腾讯，不是**处罚**腾讯。

因此每条结果都要过三道门槛：

1. **官方域名白名单**：只认 `gov.cn` / `creditchina.gov.cn` / `gsxt.gov.cn` 等
2. **企业名真实命中**：支持全称与字号两种写法
3. **证据分级**：

| 等级 | 判定条件 | 去向 |
| --- | --- | --- |
| `strong` | 统一社会信用代码命中 / 标题同时含企业名与风险关键词 | 风险库，+12 分 |
| `medium` | 标题点名企业，且正文命中 ≥2 个风险关键词 | 风险库 |
| `weak` | 仅正文提及企业名，或只命中 1 个泛化关键词 | `leads` 线索区，不入风险库 |

## 前端接入（app.js / api.js）

主界面不再全程使用 mock 数据，改由 `api.js` 统一判定数据源：

| 条件 | 数据源 | 界面表现 |
| --- | --- | --- |
| 有后端 + 已配密钥 | **真实接口** | 侧边栏 `SearchPro / gov · LIVE`，助手状态「在线 · 元宝搜索真实接口」 |
| 有后端 + 未配密钥 | 演示数据 | 侧边栏 `DEMO · 未配置腾讯云密钥`，助手顶部黄色横幅 |
| 无后端（纯静态托管） | 演示数据 | 侧边栏 `DEMO · 未连接后端网关`，助手顶部黄色横幅 |

真实模式下：

- **AI 助手**：输入企业名 → 调 `/api/inspect` → 渲染真实风险/线索、证据等级、原文链接与能力边界声明
- **巡检任务**：优先巡检勾选企业（否则台账前 3 家）→ 真实检索结果合并进风险库，高风险自动生成告警
- 演示模式下所有回答都带「演示数据」标记，并提示去 `/debug` 验证，不会把 mock 冒充真实结果

企业名解析支持三级：台账全称 → 台账字号 → 剥掉「查一下」等动词后按公司后缀匹配。

### 导入真实企业（企业台账 → 导入企业）

台账里的 35 家是虚构演示数据，搜索真实数据库永远查不到。要跑真实闭环，需要导入真实企业：

- 点「导入企业」，每行一家，支持 `企业全称` 或 `企业全称,统一社会信用代码`
- 从 Excel 复制两列直接粘贴，逗号 / 制表符 / 竖线都能识别，自动去重、跳过无效行
- 导入后标记「真实」，巡检走真实接口，结果写入风险库与告警中心
- 导入的企业与真实风险存在 `localStorage`，刷新不丢；可单独「移除」

**注意**：导入框里的灰色文字是占位提示，不是已填内容。必须自己粘贴名单，
否则点「开始导入」会在框下报「文本框是空的」。

界面上如何区分演示与真实：

| 标记 | 含义 |
| --- | --- |
| 灰色「演示」标签 | 虚构企业，检索不到任何公示 |
| 青色「真实」标签 | 用户导入的企业，走真实接口 |
| 顶部黄色横幅 | 一家真实企业都还没导入时的提醒 |
| 「隐藏 N 家演示企业」 | 一键只保留真实主体，刷新后仍生效 |

## 为什么很多企业「查不出来」

这是被问得最多的问题，答案不是代码坏了，而是这个接口的能力定位：

**元宝搜索是「主题检索」，不是「企业主体检索」。**

实测：查「新泥地（成都）人工智能科技有限公司 行政处罚」，接口返回 10 条结果，0.7 秒，
但内容全是「成都 AI 产业新闻」「行政处罚的种类有哪些」「泥地足球赛」这类页面——
**公司名一次都没出现**。因为它把长查询拆成关键词去匹配主题，而不是定位一个法人实体。

用字号码、加引号、拼信用代码都试过，结果一样：返回语义相近但与主体无关的内容。

| 你想要的 | 这个接口能不能做到 |
| --- | --- |
| 按企业名精确查处罚记录 | ❌ 做不到，长尾企业根本没有主体页 |
| 查行业监管动态、政策变化 | ✅ 很擅长 |
| 查某类风险的典型案例、判罚尺度 | ✅ 很擅长 |
| 确认一家企业是否存在 | ❌ 要用 gsxt |

所以界面上现在会明确区分三种结果，而不是一律显示「0 条风险」：

| 诊断 | 含义 | 界面表现 |
| --- | --- | --- |
| `returnedTotal > 0`，`nameMatchedTotal = 0` | 搜到了内容，但一条都没提到该企业 | 黄色提示：这是主题检索的结果，与主体无关 |
| `nameMatchedTotal > 0`，`risks = 0` | 提到了企业，但证据等级不够 | 归入待核实线索 |
| `risks > 0` | 达到采信标准 | 进入风险库 |

`/api/inspect` 返回的 `diagnostics` 数组会给出每次 Query 的 `returned`（返回条数）和
`nameMatched`（提及该企业的条数），`/debug` 自测台也会把它们逐条列出来。

**要真正做主体核查**，正确做法是接结构化数据源：

- 信用中国（creditchina.gov.cn）按统一社会信用代码查行政处罚
- 国家企业信用信息公示系统（gsxt.gov.cn）查经营异常、严重违法失信
- 企查查 / 天眼查开放平台

元宝搜索适合做这些源覆盖不到的部分：行业监管趋势、地方政策变化、招投标公告解读。

## 能力边界（重要）

这个接口是**搜索**，不是**信用数据库**。两者能回答的问题不同：

| 能做 | 不能做 |
| --- | --- |
| 发现企业相关的公开信息线索（监管动态、招投标参与、资质公示、舆情） | 判定某条处罚的**当事人是谁** |
| 提供可追溯的原文链接与信源 | 替代信用中国的结构化处罚数据 |
| 按企业名召回该主体的专属页面 | 保证召回完整（未上网的处罚查不到） |

**实测反例（务必知悉）**：查「蜜雪冰城股份有限公司 行政处罚」，命中的是
《滦平县市场监督管理局行政处罚决定书》，正文写着「当事人未经商标注册人**蜜雪冰城股份有限公司**的授权…」。
蜜雪冰城在这里是**被侵权的权利人**，真正被处罚的是那家侵权门店。
如果按「企业名 + 处罚关键词」自动定性，会得出「蜜雪冰城被行政处罚」的错误结论。

所以每条风险事件都带 `caveat` 字段，明确提示：

> 本结论由公开信息检索推断，不构成处罚认定。处罚归属请以信用中国 / 国家企业信用信息公示系统为准。

**生产环境的正确做法**：本模块定位为「线索发现」，定论必须走结构化数据源
（信用中国、国家企业信用信息公示系统、企查查/天眼查 API），或由人工复核。

## SearchPro 参数速查

| 参数 | 必选 | 说明 |
| --- | --- | --- |
| `Query` | 是 | 搜索词 |
| `Mode` | 否 | `0` 公开网页 / `1` 权威垂直信源 / `2` 混合（默认）。极速版不支持 |
| `Industry` | 否 | `gov` / `news` / `acad` / `finance`。极速版不支持 |
| `Freshness` | 否 | `d7` / `m3` / `y2` / `2026-08-20` / `2026-08-20,2026-08-30` |
| `Cnt` | 否 | `10/20/30/40/50`。极速版不支持 |
| `Site` | 否 | `qq.com` 指定域名；`exclude:qq.com\|sohu.com` 排除域名（最多 5 个） |
| `Deeplinks` | 否 | 返回附件子链，**仅旗舰版支持** |

返回 `Pages` 是 **JSON 字符串数组**，需要二次 `JSON.parse`，`tencent-wsa.js` 已处理。

关键返回字段：`title` / `url` / `date` / `passage` / `content` / `site` / `score`(0~1) /
`authority_level`(0~5，仅旗舰版) / `favicon` / `pics` / `deeplinks`。

## 版本差异

| 能力 | 极速版 lite | 标准版 standard | 旗舰版 flagship |
| --- | --- | --- | --- |
| `Mode` / `Industry` / `Cnt` | ✗ | ✓ | ✓ |
| `content` / `score` / `pics` | ✗ | ✓ | ✓ |
| `authority_level` / `Deeplinks` | ✗ | ✗ | ✓ |

风控场景建议**旗舰版**：`authority_level` 是判级和证据强度的核心依据。

## 文件

| 文件 | 作用 |
| --- | --- |
| `tencent-wsa.js` | TC3-HMAC-SHA256 签名 + SearchPro 调用，零依赖 |
| `risk-mapper.js` | 检索结果 → 风险事件/线索，含官方域名白名单与三级证据判定 |
| `company-provider.js` | 企业主体查询适配器（企查查 / 天眼查），按 `.env` 自动选择 |
| `server.js` | 静态托管 + `/api/*` 路由 |
| `env.js` | 极简 .env 加载器，供 server.js 与命令行调试共用 |
| `debug.html` | 接口自测台（`/debug`），可视化验证三步链路 |

安全说明：`server/` 目录（含 `.env`）已被静态路由拦截，直接访问 `/server/.env` 返回 403。
